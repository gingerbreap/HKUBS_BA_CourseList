# Teaching Plan 日程改动检查清单

以后每次 Programme Office 下发新 Teaching Plan 时，按本文操作。新旧 PDF **统一放在本目录**，文件名带日期后缀，便于对照。

## 1. 文件位置与命名

目录：`src/teachingPlan/`

| 角色 | 命名示例 |
|------|----------|
| 旧版（上次已同步进站） | `MSc(BA) Teaching plan 2026-27_20260814.pdf` |
| 新版（本次 PO 邮件附件） | `MSc(BA) Teaching plan 2026-27_20260903.pdf` |

约定：

- 后缀用 **PO 邮件 / 文件时间戳** 的 `YYYYMMDD`（必要时可加时分，与通知标题一致即可）。
- **不要**再把 PDF 散落在 `src/` 根目录或其他临时路径；Outlook 临时目录仅作拷贝来源。
- 同步完成后，新版即成为下一次的「旧版」。

## 2. 必查：标红与对照旧版

PO 的 Teaching Plan 用 **红色** 标出相对上一版的改动。检查时：

1. **打开新旧两份 PDF**（同目录、日期后缀相邻的两份）。
2. **不要只信邮件正文**。邮件可能只点名部分课（如只写 7002 & 7003），PDF 里仍可能有其它红字（如 7004 Tutorial 列）。
3. **逐课、逐班、逐列**扫红字，尤其注意：
   - **Lecture 日期/时间列**（含括号里的非常规时段，如 `(18:30-21:30)`）
   - **Classroom / Venue 列**（某日改教室）
   - **Tutorial / Session 列**（常在行右侧；A/B 或 C/D 常 **共用一格**，红字可能只出现一次）
   - **Exam / Final** 列
4. **标红位置 ≠ 课程代码所在行的视觉中心**：多班课程跨多行，Tutorial 列红字可能落在 7002/7004 交界，易误判所属课程。应用「最近的课程代码 + Class 字母」归属，必要时裁剪该列放大确认。
5. **红字记法常见形态**：
   - `Nov 19 (Thurs) **16 (Mon)** …` → 原周四改到周一（红的是新日期）
   - 日期后红括号时段 → 该日改为非常规时间
   - Venue 列红字 → 该日/该批日期教室变更
6. **与旧版 PDF 逐项 diff**：红字应能在旧版找到对应旧值；若新版黑字但与旧版不一致，也视为需同步（漏标或全文替换）。
7. 用工具辅助时：提取 **RGB 接近 (255,0,0) 的文本** + **按 Y 坐标映射到课程行**；再用渲染裁剪人工确认。像素/色值扫不到的框线、批注也要肉眼看一眼。

## 3. 站点数据改哪里

| 内容 | 文件 |
|------|------|
| 课表事实（日期/时间/教室/TUT） | `public/courses.json` |
| 选课页更新通知（表格数据） | `src/data/teachingPlanUpdates.ts` |
| 通知文案（中/英） | `src/i18n/locales/zh-CN.ts`、`en.ts` |
| 通知 UI / 展示规则 | `src/components/TeachingPlanUpdateNotice.tsx` |
| 页脚「最后同步」时间 | 上述 i18n 里 footer 文案中的时间戳 |

通知卡片约定：

- **新通知**默认展开；**上一则**改为折叠（仍可展开），标题带时间戳，例如 `(2026/09/03 17:23) Teaching Plan 更新已同步：7002, 7003 & 7004`。
- `updates` 里加入新 `courseCode` 会改变 dismiss version，已点「我知道了」的用户会再次看到更新后的通知。

## 4. 通知表如何写（展示规则）

表头：**课程 | 班 | 调整项 | 历史值 | 更新后**

### 班（Class）

- 讲座改动：写班别字母 `A`/`B`/`C`/`D`。
- **Tutorial 改动**：Tutorials **不绑定**某一讲座班；若本行只改 TUT，班列写 **`TUT`**，不要拆成 A+B 两行重复。
- 同一课程内：**所有 TUT 行排在该课讲座改动之后（沉底）**。

### 调整项（只写变了什么；**不要**再写 LEC/TUT 字样）

| 情形 | 调整项文案（中 / 英） |
|------|----------------------|
| 只改钟点（同日） | 时间 / Time |
| 改动跨日（日期变了） | **日期** / Date |
| 时间（或日期）+ 教室 | 时间与教室 → 若跨日则 **日期与教室** / Date & Venue |
| 只改教室 | 教室 / Venue |
| 锚定某日的场次 | `Sep 23 时间`、`Nov 9 教室` 等 |
| 同日 **同类型** 多节（如两节 LEC）才需加钟点区分 | `Sep 23 18:30-20:00 时间` |
| 同日仅是 LEC+TUT 各一节 | **不要**在调整项里写钟点；用班列 `TUT` 或班别区分 |

跨日判断：历史值与更新后文案中的日历日不同（实现上见 `involvesDateChange`）。

### 历史值 / 更新后

- **只显示有变化的字段**；未改的日期/时间/教室不要重复堆砌。
- **日期 + 教室同时改**：历史值 **只写旧日期（或旧日期时间）**，**不写原教室**。
- 历史值列：**不显示 ⏰**；更新后列：日期/时间用 ⏰，教室用 📌。
- 连续相同课程：课程名只在首行写全称；换班时课程列可只重复 **代码**；班 / 调整项相同则空白合并。

### 已选高亮

- 用户已选该课该班时，该班全部改动行浅黄高亮，班列加粗。
- `TUT` 行不按讲座班高亮。

## 5. 推荐操作顺序（给 Agent / 维护者）

1. 将新 PDF 拷入 `src/teachingPlan/`，确认旧版仍在同目录。
2. 对照旧版 + 扫新版红字，列出「课程 / 班或 TUT / 旧值 / 新值」清单（含邮件未点名的课）。
3. 改 `public/courses.json`（TUT 共用则 A/B 或 C/D 相关 meeting 一并改）。
4. 更新 `teachingPlanUpdates.ts`：新 notice 或扩展现有 notice；TUT 行 `sectionId: 'TUT'` 并沉底。
5. 更新 i18n 标题课程列表、body、页脚同步时间。
6. 本地打开选课页核对表格文案与高亮。
7. Commit + push `main`（GitHub Pages 自动部署）。
